Debounce design floor (stated, not measured): refresh at most once per 5.0s **or** once per 3 events. Observed events behind each refresh: p50 3, max 3.

> The debounce constants are WALL-CLOCK, but --speed compresses only the simulated session clock, so a scenario run at speed S faces a debounce S times stricter in session-time terms than production would. This changes how many events fall behind each refresh, and therefore the refresh cadence metric 1's curve is indexed on -- which is why each curve point also carries its event_index. It does not affect H1/H2/H3, each of which is a single operation's own cost.
