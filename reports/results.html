Architecture

One shared Semantic API, everything else reads through it

The Recommender Engine never touches Postgres, Milvus, or Neo4j for track content directly — it calls the same FastAPI Semantic API that will eventually serve Similarity Search, Auto-tagging, and Playlist Generation too. That's the one architectural decision this diagram exists to show.

Stage 2 · Ingestion

411 licensed tracks, from Jamendo to Postgres + MinIO

5 / 5 tests

Real, Creative-Commons-licensed audio pulled from the Jamendo API — deliberately kept to a 200–500 track seed rather than a full corpus, to keep CLAP inference feasible on a local CPU. Every track was fingerprinted with Chromaprint and linked to MusicBrainz where a match existed.

Stage 3 · Semantic Enrichment

CLAP embeddings that actually cluster by genre

6 / 6 tests

Every track was embedded with LAION-CLAP (512-dim, CPU-only) and indexed in Milvus; a matching Track/Artist/Genre graph was written to Neo4j. The plot below projects all 411 embeddings to 2D with t-SNE — tracks that sound alike land near each other before any genre label is consulted, which is the whole premise "semantic-aware" pipelining rests on.

Stage 4 · Semantic API

One FastAPI service, six read-only endpoints

8 / 8 tests

A single shared gateway over all three stores, built so every future L3 consumer — Recommender Engine now, Similarity Search / Auto-tagging / Playlist Generation later — reuses it instead of re-implementing its own store access.

Stage 5 · Recommender Engine

Similarity plus two graph-derived boosts, additively combined

8 / 8 tests

A trigger is a single existing track — "this was just played" — with no fabricated user or session identity, since no behavioral data exists anywhere in this pipeline yet. For each trigger, three HTTP calls to the Semantic API gather candidates; a pure-function ranker scores them:

SignalWeightWhy
CLAP cosine similarityas-is (~0–1)the primary acoustic signal

same artist (Neo4j)+0.15precise: ~2.0 tracks/artist on average

Stage 6 · End-to-End Test

A lineage test, not a fresh rebuild

5 / 5 tests

Three golden tracks were traced through all five stages — Postgres & MinIO, Milvus & Neo4j, the Semantic API, and a freshly-run Recommender pass — asserting the same title, artist, and genres hold at every hop. Run against the live, already-verified stack rather than a destructive from-scratch rebuild (that sequence is documented as an on-demand runbook instead). Building it surfaced one real bug: the API and the test suite's own Milvus fixture were silently sharing a connection alias, so a test in one file could break Milvus for tests in another file that ran after it — fixed by giving the API its own dedicated alias.
